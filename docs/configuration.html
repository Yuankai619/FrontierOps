Reading this file

Only project.id and project.name are required when writing a file from scratch; Setup creates them. Omitted fields take the defaults below. Unknown fields fail validation. Relative paths are resolved against the directory containing frontier.yaml, except the video script, which Render also resolves from that directory. Run frontier config validate --config frontier.yaml after editing and frontier schema config --format json for machine-readable types.

Use stable profile.topics[].id values across searches. Changing a date window under the same ID allows Discovery to report what entered the new scope; it does not claim that every returned paper was just published. The checked-in frontier.yaml.example is an offline development fixture, not your active file. The Config Skill writes a *.candidate.yaml proposal, validates and diffs it, then applies it to frontier.yaml.

schema_version: "0.1"
project: {id: agent-harness, name: Agent Harness Watch}
sources:
  openalex: {enabled: true, mode: live, max_results: 200}
profile:
  topics:
    - id: agent-harness
      description: execution harnesses for AI coding agents
      search:
        providers: [openalex]
        query: 'agent harness coding'
        published_from: 2026-01-01
brief:
  outputs: [html, slides]

Dates use YYYY-MM-DD. The OpenAlex query searches title, abstract, and keywords; the topic description and profile keywords drive the separate local relevance score.

Sources

Every source starts disabled. Set enabled: true and, for remote sources, mode: live before expecting network results. Fixture mode requires a JSON fixture_path; it is for testing, not a substitute for a live subscription. Provider keys and passwords never belong in YAML; see Credentials.

SourceLive behavior and required target
sources.openalexTopic works search. Requires at least one profile.topics[].search.providers containing openalex. Paginates each bounded query up to max_results; reports truncation. API key optional for basic use.
sources.alphaxivMCP discover_papers for a topic; requires a topic provider entry and 3–4 search.keywords. Needs an API key for this harness's headless client. Returns a small ranked top-k, never a complete corpus.
sources.arxivarXiv Atom API. Live mode requires paper_ids, queries, or categories. It does not use profile.topics[].search to form its query.
sources.semantic_scholarTracks papers of stable Semantic Scholar author IDs from tracking.scholars. It is not a general keyword search adapter. API key optional, subject to upstream limits.
sources.openreviewOpenReview API 2 submission invitations for tracking.venues. Requires a token or username and password. Venue selection does not automatically cover every conference or year.
sources.local_libraryReads files under configured local roots, no remote credential. PDF uses PyMuPDF; Markdown and text use a plain-text parser.

Scholar and venue tracking

tracking.scholars and tracking.venues default to empty lists. Display names are not stable identities. Currently, live scholar fetching is implemented only for Semantic Scholar author IDs; google_scholar is accepted in the schema but has no live adapter.

Field within itemDefault / effect
tracking.scholars[].idRequired local stable ID for your subscription.
tracking.scholars[].nameRequired display name; not used as the remote lookup key.
tracking.scholars[].aliasesEmpty list; stored for identity context, not used by the live fetcher.
tracking.scholars[].identitiesRequired mapping; set semantic_scholar: <author-id> to use the current live author adapter.
tracking.scholars[].providersRequired list of semantic_scholar, arxiv, or google_scholar; only Semantic Scholar author tracking is currently wired to a live scholar-specific fetcher.
tracking.scholars[].backfill_days365; accepted but not applied by the current author fetcher.
tracking.scholars[].always_include_new_publicationstrue; accepted, but no bypass of ranking Gates is currently implemented.
tracking.venues[].providerRequired literal openreview.
tracking.venues[].venue_idRequired exact OpenReview group ID, including year, such as ICLR.cc/2026/Conference.
tracking.venues[].decisionsEmpty list means no decision filter. When nonempty, the current adapter filters only notes with a detected decision; notes without one remain, so do not treat this as a strict accepted-only guarantee.

Research profile and topic search

profile defaults to empty topics and keyword lists. profile.topics[].search is optional until a topic provider is enabled. Topic search determines what OpenAlex/alphaXiv request; the topic description and include keywords separately determine the local lexical relevance feature. The search query is not a perfect semantic relevance gate.

FieldDefault / effect
profile.topics[].idRequired stable topic ID; keep it unchanged across runs to compare the same interest.
profile.topics[].descriptionRequired description; its words become weighted lexical relevance terms.
profile.topics[].weight1.0, nonnegative; weights description terms in lexical relevance, not the API query or final score directly.
profile.topics[].search.providersEmpty list; choose openalex, alphaxiv, or both. The corresponding source must also be enabled in live mode.
profile.topics[].search.queryRequired when search exists. Sent to OpenAlex title/abstract/keywords search and as alphaXiv's semantic question.
profile.topics[].search.keywordsEmpty list; alphaXiv requires exactly 3–4 concise terms. OpenAlex does not use this list.
profile.topics[].search.published_fromUnset; inclusive lower publication-date boundary.
profile.topics[].search.published_toUnset; inclusive upper publication-date boundary; cannot precede published_from.
profile.topics[].search.alphaxiv_difficulty5, 1–10; retrieval-effort setting for alphaXiv only.
profile.keywords.includeEmpty list; contributes English/alphanumeric terms to lexical relevance.
profile.keywords.excludeEmpty list; matching text forces lexical relevance to 0, but is not itself a hard exclusion. Add a relevance Gate if a hard cutoff is needed.

Gates and ranking

A Gate decides whether a candidate is excluded, warned, or exempted; enabled ranking.features weights order candidates afterward. A score measures the configured heuristic, not scientific quality. ranking.gates defaults to an empty list: no paper is excluded by default.

ranking:
  gates:
    - {id: recent, type: publication_year, min_year: 2025, on_fail: exclude}
    - {id: citations, type: citation, minimum_count: 3, exempt_if_age_days_lte: 90, on_fail: warn}
    - {id: topical, type: relevance, minimum: 0.25, on_fail: exclude}
FieldDefault / effect
ranking.gates[].idRequired label shown in the Gate trace.
ranking.gates[].typeRequired: publication_year, citation, or relevance.
ranking.gates[].enabledtrue; disabled Gate is reported as exempt.
ranking.gates[].on_failexclude or warn; default exclude.
ranking.gates[].min_yearRequired for publication_year; missing publication year fails the Gate.
ranking.gates[].minimum_countRequired nonnegative citation threshold for citation. Missing citation data warns regardless of on_fail.
ranking.gates[].exempt_if_age_days_lte0; exempt a paper this many days old or newer from a citation Gate when age is known.
ranking.gates[].minimumRequired 0–1 lexical score threshold for relevance.
ranking.features.lexical_relevance{enabled: true, weight: 0.55}; title + abstract overlap with description/include terms.
ranking.features.citation{enabled: true, weight: 0.15}; logarithmic citation count, clipped at 1.
ranking.features.freshness{enabled: true, weight: 0.15}; decay from publication date.
ranking.features.reliability{enabled: true, weight: 0.15}; configured value for the source provider; an absent provider value contributes 0.
ranking.features.*.enabledBoolean switch for each feature.
ranking.features.*.weightNonnegative weight. Enabled weights are normalized by their sum; all zero weights give a score of 0.
ranking.citation_scale100, positive; count at which the citation feature reaches 1.
ranking.freshness_half_life_days180, positive; freshness halves after this many days.
ranking.source_reliabilityEmpty mapping; provider names to numeric feature values. Prefer 0–1 values; the schema does not enforce that range.
ranking.deep_enrich_top_k5, positive; attempt deterministic explanation/full-text enrichment for the top eligible candidates.
ranking.max_fulltext_pages20, positive; limit local full-text pages used for enrichment/visual extraction. Does not cap an alphaXiv MCP response.

Sync policy

Sync runs only after a researcher requests Discover or an operator invokes the CLI. The current implementation compares stable provider IDs and content fingerprints with saved state; topical searches also preserve every current observation for cross-run comparison.

FieldDefault / effect
sync.trigger_modeOnly manual is accepted; no scheduler.
sync.baselineOnly last_successful_sync is accepted; current state is stored in .frontier/state/.
sync.default_lookback_days14; accepted but not yet applied to live provider queries.
sync.on_provider_errorfail or partial; default fail. Current Sync does not yet implement partial recovery; a provider exception stops the run in either mode.
sync.preserve_raw_responsestrue; accepted, but the current repository always caches normalized source-record snapshots, not the original HTTP response body.
