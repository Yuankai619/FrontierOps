下列 CLI 供 Skill 操作，也方便開發者逐階段除錯。一般研究者只需輸入四個 Skill 動作。

如何執行

在原始碼 checkout，每個 frontier 前加 uv run --locked；用 Setup 安裝為 uv tool 後直接執行 frontier。這兩種方式都不會把 source code 複製進研究 workspace。

uv run --locked frontier --help
frontier --help

設定與來源

命令作用
frontier setup --workspace PATH --name NAME建立 active YAML 與公開輸出資料夾；不覆寫既有 YAML。
frontier schema config --format json印出設定 schema、預設值及型別。
frontier config inspect/validate --config PATH讀取解析後設定或檢查錯誤；不改檔。
frontier config draft --config PATH --output PATH複製為候選 YAML；接著 Agent 編輯這份候選。
frontier config diff --old PATH --new PATH列出欄位層級差異。
frontier config apply --candidate PATH --config PATH驗證候選後更新 active YAML。
frontier scholar/venue resolve ...查穩定 ID 候選；目前 resolver 是離線 fixture，不代表 live 訂閱成功。

一次 Run 的內部階段

命令讀取、寫入與失敗情況
frontier build --config PATH驗證 YAML，建立 Run 與設定快照；不抓論文。
frontier sync --config PATH使用者觸發後抓資料，依上次成功狀態產生新／更新訊號；輸出 Run 絕對路徑。來源錯誤會留在 stage result。
frontier rank --run PATH對該 Run 的訊號做 Gate、排序與 Evidence 擷取，產生 Discover 頁。不會把舊論文重算成新論文。
frontier discovery serve --run PATH開啟只綁本機的互動頁，驗證並保存選取檔。終止服務後，已儲存的 JSON 仍在 Run。
frontier brief --run PATH讀同一 Run 的候選與選取檔，寫可修改的草稿；自動抽句需回原文檢查。
frontier review --run PATH核對來源 ID、數字、精確引句和規則；失敗時阻止 Render。無法取代語意審稿。
frontier render --run PATH只從 approved spec 產生 HTML、OpenSlide 與可選影片 preview；每篇有獨立 HTML／slides 專案。

Rank、Brief、Review、Render 均須傳入同一個 Run 路徑。不能從新 Run 取排名、拿舊 Run 的 Evidence 發布。
