使用文件

從安裝 Agent Skill 到產出可查核的 HTML 與簡報。研究者用自然語言下達四個動作；CLI 與中間產物供 Agent 執行和除錯。

Quick Start

需要 uv >=0.12.20, <0.14。要建置 OpenSlide，還需要 Node.js 與 npm。先選一個 Coding Agent 安裝 FrontierOps plugin；plugin 提供四個 Skill，Python Harness 會在 Setup 時另外安裝。

安裝 Agent Skill

Claude Code

claude plugin marketplace add Yuankai619/FrontierOps
claude plugin install frontierops@frontierops

Codex CLI

codex plugin marketplace add Yuankai619/FrontierOps
codex plugin add frontierops@frontierops

GitHub Copilot CLI

copilot plugin install Yuankai619/FrontierOps:plugins/frontierops

以上是本專案提供的安裝命令；此次 AutoSci 實跑是在 Codex 依 Skill 檔案操作本機 checkout，尚未跨三種宿主實測遠端安裝。若宿主 CLI 版本有變，先查該 CLI 的 plugin --help；語法可對照 Claude Code、Codex 與 Copilot CLI 官方文件。Copilot 指 Copilot CLI，不代表所有 Copilot 介面。

然後對 Agent 說

「使用 frontier-setup，在目前研究 workspace 設定 FrontierOps。」

Setup 建立實際使用的 frontier.yaml 和 frontier_output/。接著請 Config 設定來源、請 Discover 檢查新論文、最後請 Briefing 解說選中的論文。frontier.yaml.example 是 repo 內的離線測試檔，不是你的 active 設定。

四個使用步驟

1. Setup：建立 workspace

輸入工作目錄與專案名稱。Skill 檢查 uv、Git、Node/npm，安裝／載入 Harness，執行 frontier setup 並驗證設定。既有 YAML 不會被覆寫。

交付：frontier.yaml、frontier_output/ 的路徑，以及哪些可選相依尚未安裝。

2. Config：把研究需求寫進 YAML

輸入研究主題、論文 ID／本地 PDF 資料夾／學者／會議、篩選條件、時長與格式。資訊不足時 Agent 應詢問，不猜學者 ID 或 citation threshold。它先產生候選 YAML、驗證與顯示差異，再套用。

交付：已驗證的 active frontier.yaml；不會自動觸發 Sync。

3. Discover：你要求時才比較更新

Agent 執行 Sync 與 Rank，對比上次成功同步後的新訊號，顯示合格／排除原因。Gate 決定資格，權重決定排序；分數不是論文品質或真偽機率。

交付：Run 絕對路徑與 frontier_output/discoveries/<run-id>.html。下一步必須沿用同一個 Run。

4. Briefing：核對原文後發布

選定論文和 Discover Run。Agent 檢查草稿的問題、方法、實驗與限制是否真的受 PDF 支持；Review 通過後才 Render。HTML 與 OpenSlide 共用同一份核准內容。

交付：frontier_output/briefings/<run-id>/。投影片原始專案在 slides/；進入該目錄建置後才有 dist/。

用 AutoSci 跑一次

先把 AutoSci PDF 放進獨立測試 workspace 的 data/library/。以下可直接貼給已載入 plugin 的 Agent；把 <ADSL> 換成你本機的絕對路徑。

Setup

使用 frontier-setup，在 <ADSL>/FrontierOps_test/autosci-example 建立名為 AutoSci 的 workspace。檢查環境，建立並驗證 active YAML，不要同步。

Config

使用 frontier-config，只讀取 data/library 內的 AutoSci PDF。主題是 automated scientific research 與 persistent memory；輸出 HTML 和 slides，不做影片。不要設定 citation Gate。先 draft、validate、diff，再 apply。

Discover

使用 frontier-discover，現在執行 Sync 和 Rank，告訴我新增論文、篩選理由、Discovery HTML 與 Run 絕對路徑；不要自動 Briefing。

Briefing

使用 frontier-briefing，沿用剛才的 Run，解釋 AutoSci 的問題、四個模組、案例與限制。逐條對照 PDF 頁碼，修正錯誤抽句，再 Review 和 Render；只驗收 HTML 與 OpenSlide build。

每一步的輸入、輸出與實測缺陷記在 完整 AutoSci 範例。它顯示首次 Sync 新增 1 筆、第二次新增 0 筆；也記錄自動抽句錯誤與 Agent 如何修正。

frontier.yaml 設定參考

所有範圍、Gate、排序權重、時長與輸出格式都在 active YAML，沒有藏在 Skill prompt 裡的固定門檻。Config Skill 會保留未要求改動的既有值；未知欄位會驗證失敗。路徑相對於 YAML 所在目錄。

一份可驗證的最小範例

schema_version: "0.1"
project:
  id: autosci
  name: AutoSci
  language: en
sources:
  local_library:
    enabled: true
    roots: [data/library]
profile:
  topics:
    - id: auto-research
      description: Automated scientific research and agent harnesses
      weight: 1.0
ranking:
  gates: []
  features:
    citation: {enabled: false, weight: 0.0}
brief:
  target_duration_seconds: 300
  maximum_seconds_per_development: 300
  outputs: [html, slides]
rendering:
  video: {enabled: false}

其餘欄位由 schema 預設補上。這個範例不使用 live API；把 PDF 放進 data/library/ 後才有資料。語言欄位不會自動翻譯 PDF 抽句。

區塊用途與常改欄位
projectid、name、language；workspace_dir 預設 .frontier，output_dir 預設 frontier_output。
sources啟用 local_library、arXiv、Semantic Scholar 或 OpenReview；本地庫用 roots。Live API 可設定逾時、限速及 key 的環境變數名稱，不要把 secret 值寫進 YAML。
trackingscholars 使用 provider stable ID；venues 使用 stable venue ID。同名者須人工確認。Google Scholar live adapter 尚未實作。
profiletopics[].description/weight 表達研究興趣；keywords.include/exclude 輔助相關度。
rankinggates 是資格門檻；features.*.weight 是通過 Gate 後的排序權重；max_fulltext_pages 控制讀取頁數。
synctrigger_mode: manual；以 last_successful_sync 為比較基準。on_provider_error 可選 fail 或 partial。
brieftarget_duration_seconds 預設 300，可自訂；outputs 可選 html、slides、video。
review控制缺證據、斷鏈、無來源數字、重複及超時是否阻擋發布；不能替代原文語意查核。
rendering.video預設關閉；要啟用需另備 HeyGen TTS adapter 並核准影音成本。影片 preview 不等於 MP4。

Gate 與權重的差別

Gate 先問「可不可以入選？」例如年份或最低引用數；結果留下通過、排除、警示或新論文豁免紀錄。權重只對合格項目排序。新預印本通常沒有可靠 citation count，請勿機械套上固定引用門檻。

ranking:
  gates:
    - id: citations
      type: citation
      minimum_count: 3
      exempt_if_age_days_lte: 90
      on_fail: warn

完整欄位、預設值與型別以 frontier schema config --format json 為準；進一步說明見 完整使用手冊。

指令參考

這些是 Agent Skill 使用的 Harness CLI，通常不需要研究者逐段執行。在原始碼 checkout 中，以下每個 frontier 前加 uv run --locked；安裝為獨立工具後直接用 frontier。

指令作用
frontier setup --workspace PATH --name NAME建立 active YAML 與公開輸出資料夾；不覆蓋既有設定。
frontier schema config --format json印出設定 schema 與預設值。
frontier config inspect --config PATH讀取展開後設定，不修改檔案。
frontier config validate --config PATH檢查欄位與值，不修改檔案。
frontier config draft --config PATH --output PATH建立候選 YAML，不直接改 active 設定。
frontier config diff --old PATH --new PATH列出欄位層級差異。
frontier config apply --candidate PATH --config PATH驗證後套用候選設定。
frontier scholar resolve --name NAME --provider semantic_scholar查學者 stable ID 候選；目前 resolver 使用離線 fixture。
frontier venue resolve --name NAME --year YEAR --provider openreview查會議 stable ID 候選；目前 resolver 使用離線 fixture。
frontier build --config PATH驗證設定並初始化 Run；不擷取來源。
frontier sync --config PATH使用者要求時才抓取增量；印出 Run 絕對路徑。
frontier rank --run PATHGate、排序、產生 Discovery HTML 與 Evidence。
frontier brief --run PATH建立可編輯的解說草稿。
frontier review --run PATH檢查並核准或阻擋草稿。
frontier render --run PATH只從核准內容產生 HTML、OpenSlide 或可選影片預覽。

Discover 的 Sync/Rank 和 Briefing 的 Brief/Review/Render 都用同一個 Run 路徑。不要對新 Run 重新 Rank，再拿舊 Run 去 Render。

輸出與過往紀錄

研究 workspace/
├── frontier.yaml              # active 設定
├── data/library/              # 你提供的 PDF
├── .frontier/
│   ├── runs/<run-id>/          # 六階段、Evidence、Review 與 Run Manifest
│   ├── state/                  # 上次成功同步的 cursor
│   └── cache/raw/              # 原始來源快照
└── frontier_output/
    ├── discoveries/<run-id>.html
    └── briefings/<run-id>/
        ├── html/index.html
        ├── slides/             # OpenSlide 原始專案
        └── manifest.json

新 Run 不覆蓋舊 Run。Render 同一 Run 多次也會保留新的公開資料夾；請讀 05-render/render-result.json 的 public_output_dir，不要只猜目錄名。OpenSlide 專案需在 slides/ 內執行：

npm install
npm run sync:skills
npm run build
npm run preview

預覽伺服器會印出本機網址；在該網址後面加 /s/frontier-briefing 開啟 deck。沒有自動匯出 PPTX 或 PDF。

目前限制

  • 自動抽句是 deterministic heuristic，可能挑到附錄或不相干段落。Agent 必須在 Review 前核對原始 PDF；Review 本身不做語意推理。
  • 本地 PDF 標題目前取自檔名；沒有可靠的引用數與發布日期時，citation／freshness 分數不可解讀成論文品質。
  • AutoSci 實跑驗收了 HTML 互動與 OpenSlide build；沒有驗收影片、三種宿主的遠端 plugin 安裝或正式研究品質評估。
