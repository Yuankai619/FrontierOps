輸出與紀錄

設定、原始資料、每次執行與公開成果分開保存。不要從資料夾名稱猜最新輸出，應讀 Run manifest。

Quick Start四個使用步驟AutoSci 範例frontier.yaml指令參考輸出與紀錄

工作區結構

research-workspace/
├── frontier.yaml                     # 唯一生效設定
├── data/library/                    # 本地 PDF 與同名 .pdf.json
├── .frontier/
│   ├── config-drafts/              # Config 候選稿
│   ├── state/                      # 上次成功 Sync 的 cursor
│   ├── cache/raw/                  # 原始來源快照
│   └── runs/<run-id>/
│       ├── 01-sync/               # 新增、更新、重複數量
│       ├── 02-rank/               # 候選、Evidence、選取檔
│       ├── 03-brief/              # 可修訂草稿
│       ├── 04-review/             # 審核結果
│       ├── 05-render/             # 內部渲染結果
│       └── run-manifest.json
└── frontier_output/
    ├── discoveries/<run-id>.html
    └── briefings/<run-id>/
        ├── index.html             # 成果目錄
        ├── manifest.json          # 逐篇輸出路徑
        └── papers/paper-1/
            ├── html/index.html
            └── slides/            # 可編輯 OpenSlide 專案

Discover 之後

Discover 頁面顯示本次新／更新、前幾次 Run 的數量與舊論文清單。舊論文不套新設定重新計分。選取頁在本機服務模式下寫入 02-rank/briefing-selection.json，包含 Run ID 與合格 candidate ID；瀏覽器不能把修改直接存回 HTML 檔。沒有資料庫。

Briefing 之後

05-render/render-result.json.public_output_dir 指向這次實際發布的資料夾。每篇 HTML 與 slide 專案在 papers/paper-N/，總覽版保留作舊流程相容。同一 Run 重做 Render 會產生帶序號的新公開資料夾，不覆蓋舊成果。

進入某篇的 slides/ 執行：

npm install
npm run sync:skills
npm run build

建置後在 OpenSlide 的 /s/frontier-briefing 路由展示；系統目前不自動匯出 PPTX 或 PDF。影片 preview 仍以整個 Run 為單位，未拆成逐篇成品。
