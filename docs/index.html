FrontierOps
設計邏輯快速開始指令設定完整手冊

從新論文，到值得討論的研究理解。

FrontierOps 把來源、證據、篩選決策與解釋保存成可查核的研究簡報流程。研究人員按下 Sync 才更新；既有 Coding Agent 負責深入閱讀，Harness 確保每個結論都能回到原文。

設計邏輯

先理解一篇論文，再決定怎麼呈現

一篇新論文不應只變成一張摘要卡。FrontierOps 的核心解釋依序回答：原本的問題、作者的做法、實驗真正支持的結論，以及仍待驗證的限制。

01Build驗證設定，建立可追溯的 Run。
02Sync使用者觸發，與上次成功同步比較。
03Rank套用 Gate，顯示取捨原因與分數。
04Brief把論文問題與證據寫成有時間預算的說明。
05Review阻擋沒有來源的數字、失效引用與超時內容。
06Render從核准內容產生互動 HTML、OpenSlide 與影片預覽。

相同內容，多種閱讀方式

HTML 可以切換論文問題、展開 Evidence、放大原文 Figure，再回到 PDF 原頁。OpenSlide 使用一頁一個主論點的學術簡報結構。影片先提供有旁白與字幕的可審閱場景。

圖像要有來源

優先擷取使用者提供的論文 Figure 或關鍵段落，標明頁碼、caption 與來源。找不到可信素材時明示缺漏；不以假圖、無關漸層或重複卡片格冒充研究解釋。

架構界線：Domain 定義契約，Application 編排流程，Adapters 接外部 API、檔案與 renderer；Coding Agent 透過 Skill 使用 Harness，系統不內建另一個 Agent framework。

快速開始

用凍結資料跑通一次流程

需要 Python 3.12 與 uv。範例設定使用離線 arXiv／OpenReview fixture，不需 API key；之後再切換 live provider。請在 repo 根目錄執行。

uv sync --locked
uv run --locked frontier config validate --config frontier.yaml.example
uv run --locked frontier sync --config frontier.yaml.example

Sync 會印出本次 Run 的絕對路徑。以下所有 <run-path> 都替換成同一個路徑；不要混用另一次 Build 的 Run。

uv run --locked frontier rank --run <run-path>
uv run --locked frontier brief --run <run-path>
uv run --locked frontier review --run <run-path>
uv run --locked frontier render --run <run-path>
  1. 打開 <run-path>/05-render/briefing.html：切換問題、展開證據並檢查 PDF 連結。
  2. 到 <run-path>/05-render/open-slide/ 執行 npm install、npm run build、npm run preview，開啟 /s/frontier-briefing；OpenSlide 工具列可匯出 PDF。
  3. 影片須先在 05-render/hyperframes/ 執行 npx hyperframes check、npx hyperframes preview --background；使用者審閱核准後才編碼 MP4。預設 fixture 不啟用 HeyGen，因此不會有影片。
指令索引

每個指令都有明確邊界

以下省略共同前綴 uv run --locked frontier。所有 Run 後續階段都接同一個 --run PATH。

指令用途
schema config --format json查看嚴格的 YAML 設定契約與預設值。
config inspect --config PATH讀取並展開設定，不改檔案。
config validate --config PATH拒絕未知欄位及無效門檻。
config draft --config PATH --output PATH建立可審核的候選 YAML。
config diff --old PATH --new PATH比較欄位修改前後值。
config apply --candidate PATH --config PATH驗證通過後才原子更新 active YAML。
scholar resolve --name NAME --provider semantic_scholar查 stable author ID 候選；同名需人工確認。目前為離線 resolver fixture。
venue resolve --name NAME --year YEAR --provider openreview查 stable venue ID 候選；目前為離線 resolver fixture。
build --config PATH驗證設定，建立 Run；不抓取新資料。
sync --config PATH使用者主動觸發 Build 與來源 delta sync。
rank --run PATH套用 Gate，排序並保存可查核 Evidence。
brief --run PATH產生有時間預算的論文解釋草稿。
review --run PATH檢查事實、來源、重複與時間；通過後核准。
render --run PATH從已核准的 spec 產生目標格式。
設定與追溯

規則在 YAML，歷史留在 Run

frontier.yaml 控制研究範圍、來源、Gate、時間和輸出。未知欄位會驗證失敗；API key 只填環境變數名稱，不寫入金鑰本身。每個欄位的完整定義見使用手冊。

設定區塊你會改什麼
project專案 ID、名稱、時區、語言與工作目錄。
profile研究主題、主題權重、偏好與排除關鍵詞。
tracking要追蹤的學者 stable ID、別名與 OpenReview venue。Google Scholar live 尚未接入。
sourcesarXiv、Semantic Scholar、OpenReview 的 fixture/live 模式與本地 PDF 目錄、限速、憑證環境變數名稱。
sync手動觸發、以上次成功 Sync 為基準、初次回看天數與來源錯誤處理。
ranking.gates年份、引用數或相關度資格門檻；可排除、警示或豁免新論文。
ranking.features合格候選的相關度、引用、新鮮度與來源可靠性權重。
brief預設 300 秒，可改成任何正數秒數；項目上限、語速與目標格式。
review對無證據、失效來源、無依據數字、重複和超時的阻擋政策。
rendering.video是否啟用 HeyGen／HyperFrames preview、語音、畫布、fps 與品質。

Gate 不等於分數

Gate 先判定候選是否具備入選資格，並留下 pass、exclude、warn 或 exempt。例如新論文可豁免引用數門檻；其餘合格論文才依權重排序。

每次執行都可回查

.frontier/runs/<run-id>/ 保留六階段產物和 Run Manifest；.frontier/state/ 記錄上次成功同步，.frontier/cache/raw/ 保留來源快照。新 Run 不覆蓋舊 Run。

需要自然語言修改設定時，用 frontier-config Skill 的 draft → validate → diff → apply；需要讓 Coding Agent 跑完整簡報與檢查媒體時，使用 frontier-briefing Skill。
