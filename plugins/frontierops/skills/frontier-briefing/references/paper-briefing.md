# 研究論文解說的編輯準則

讀者應能在兩分鐘內知道研究問題、主要貢獻及證據強弱。以下是編輯檢查，不是要求每篇論文套同一套固定標題。

1. **先核對書目。**標題、作者、機構、日期、發表場域應能回到論文首頁或出版頁。arXiv 上架不等於會議接受；未查得的欄位留空。若從 PDF 匯入，將核對資料放在同名 `.pdf.json`，讓後續 Run 也能使用。
2. **先寫四句摘要，再展開。**一句交代問題與重要性，一句交代方法的核心機制，一句說明最有代表性的實驗結果，一句指出實驗未證明的部分。對概念／系統設計論文，沒有可信的對照實驗時應明說，不必硬湊優勢數字。
3. **問題、貢獻、方法不要混在一起。**問題回答「為何現有方法不足」；貢獻回答「作者提出什麼」；方法回答「機制怎樣運作、為何這樣設計」。比較既有工作時，標示論文提供的比較依據，避免把作者自述當成客觀定論。
4. **實驗須有解讀。**列出任務／資料、基準、度量、主要結果與限制；只選真正支持主要主張的結果。自動 reviewer 的評分不能寫成人類審稿結果。
5. **先用原圖。**優先選最能說明機制或結果的一張原論文圖，標示 figure 編號與頁碼，並在旁邊說明讀者應看哪個部分。沒有可核對的圖時，可在 `source_excerpts` 放原文中的精確引句與 Evidence ID；Review 會檢查逐字相符。不要生成冒充論文證據的示意圖。
6. **給出可質疑的結論。**分開寫作者報告、Agent 的詮釋與未檢驗的推論。限制不是例行的禮貌段落，要點名樣本、比較、度量或可重現性的具體缺口。
7. **刪掉空話。**不用「突破性」「全面革新」「值得關注」代替機制或結果；不用每頁都有小標、三欄卡片、全大寫標籤。投影片一頁只講一個可由圖或數據支撐的重點；較完整的推理與引文放 HTML。看不出哪個資料支持句子時，刪掉或改成待核對。

參考依據：[Stanford CS167 的讀論文五問](https://cs.stanford.edu/~rishig/courses/ref/paper-reading-overview.pdf)、[MIT CSAIL 的 paper presentation 指引](https://csg.csail.mit.edu/6.S983/presentations/)、[MIT Communication Lab 的簡報準則](https://mitcommlab.mit.edu/broad/commkit/slideshow/)。這些來源都強調問題、主要貢獻、方法直覺、關鍵實驗及限制，而非逐頁轉述論文。
